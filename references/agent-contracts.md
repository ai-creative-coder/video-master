# 多 Agent 契约

## 共享规则

- 只使用主 Agent 建立的真实镜头、剧情片段和原视频证据。
- 每条判断附镜号、时间码和证据等级。
- 不分析爆款原因，不擅自改编。
- 参考视频只用于分析；面向生成的文本必须自包含。
- 每个 Agent 只接收本专业需要的证据，不接收其他 Agent 的完整报告。
- 输出使用镜号、剧情段和资产 ID 对齐的结构化字段；不写开场白、视频摘要、创作感想或泛化建议。
- 内部结果只记录新增判断和冲突，不展开已存在的资产描述。完整自然语言只在最终提示词中出现一次。

## 标准模式合并角色

标准模式不照搬深度模式的专业人数，而是合并职责并保持字段所有权唯一：

- 视觉综合 Agent 独占可见画面事实：真实镜头、每镜 `present_entities`、`action_beats[]` 的可观察动作、跨镜微事件/物体所有权转移、人物可见表演链、动态首次登场、分层文字/VFX、摄影、逐镜光影、美术资产和真实切点；同时独占标准模式的全片 `visual_master`。
- 叙事与声音综合 Agent 是条件角色，只用 `shot_id/beat_id` 补充故事因果、人物意图、影响表演的情绪、对白/字幕/口型、音乐、环境声、拟音和混音；不得重写可见动作或其他视觉字段。
- 主 Agent 独占冲突裁决、跨字段合并和最终提示词编译，并执行本文件“Seedance 生成导演”的同一套输入预检、`NEEDS_INPUT` 停止机制、schema 4.0 和去重规则。

叙事与声音综合 Agent 的启动门槛见 [standard-workflow.md](standard-workflow.md)。跳过只能减少分析过程，不能删掉输出 schema 中的声音或叙事字段；无相关内容时写有证据的最低状态，不得留空或虚构。

## 视频取证与拉片 Agent

读取媒体参数，裁决真实切镜、黑场、闪白、叠化、变速和 VFX；输出真实镜头与动态剧情片段，不按固定时长切分。为每个真实镜头至少选择一张代表帧。读取音频瞬态候选，对候选点前后约 0.20 秒加密抽帧；候选只表示需复核，不代表事件类型已经确认。

## 导演 Agent

只负责镜头功能、人物调度、可见表演链、动态首次登场、跨镜微事件与物体所有权转移、剧情段边界和专业冲突裁决。逐镜锁定 `present_entities`；人物表演按情绪意图、可见表情、视线、预备、执行、延续与收势形成连续链，且只能绑定当前镜头可见人物。

每位人物首次可见时登记出现前状态、具体来源空间、揭示触发、进入方向与画面区域、最先露出部位、初态、揭示动作、第一动作、完整建立状态和观察者反应；引用至少两张属于该镜的证据帧，动作式登场优先三帧。首次登场不能仅写“硬切出现”，除非切后首帧已经完整建立且没有可见进入动作。

对小物体快速运动、方向改变、抓取/接取、携带返回和人物视线追踪做逐镜复核；跨镜阶段使用同一 `interaction_chain_id`、`interaction_kind`、`interaction_object_ids`，记录 `interaction_phase`、`state_in`、`state_out`。所有权转移必须依次覆盖触发/踢飞、接触/抓取、携带/返回、结果/观察者反应四类阶段，上一阶段 `state_out` 原样成为下一阶段 `state_in`。例如地面物被人物踢起、飞行动物在空中接取、携物飞回、人物抬头追视必须拆成有对象状态转移的连续阶段，不得压缩为“鸟飞过”。对冲击事件验证“可见原因→目标→即时反应→物理结果”，不得把结果倒推成未经证实的主动动作。

## 编剧 Agent

只还原故事结构、人物关系、动作意图、可确认对白/旁白和表演节拍。人物动作补充影响剧情的情绪意图，但不得把上一镜情绪、反应或物理反馈复制到下一镜；每条结论必须绑定 `shot_id/beat_id` 和本镜可见人物。原片未呈现的动机或结局标 `UNKNOWN`。

## 摄影指导 Agent

只逐镜分析景别、机位、角度、构图、运镜、曝光、光向、焦点和景深，并输出 `RECREATION_SPEC`：建议摄影设备、镜头名称或类型、焦段、光圈、机位和运镜。光源方向、强弱和曝光归摄影；物体固有色、服装、材质和场景陈设归美术。不要复述剧情或资产外观，也不得因为画面主体小、运动快而替导演删减或改写动作因果。无法从视频确认原始器材时明确这是复刻方案，不输出虚假实测值。提示词编译时由构建器把本镜方案追加到对应时间轴节点末尾，不在【氛围质感】另写一套。

## 美术指导 Agent

建立人物、主要道具、车辆和场景资产库，并独占深度模式的全片 `visual_master`。每项资产包含代表帧、详细自然语言生成提示词、叙事功能、连续性锁定和证据等级。人物外观、服装、物体固有色、材质和空间陈设归美术；曝光、光源方向和摄影参数归摄影。`description_prompt` 只写静态身份与外观，不混入其他剧情段的动作和姿态；`continuity_lock` 只写额外不变量，不重抄外观。提示词不能依赖“如图”或参考视频。

`visual_master` 必须包含：

- `core_style`：贯穿全片的类型融合、时代语言、写实/风格化程度、世界与材质审美。
- `visual_tone`：全片稳定的情绪温度、秩序感或粗粝度、画面密度与观看感受。
- `color_system`：主色、辅色、强调色、冷暖关系、饱和度层级，以及人物或道具如何成为色彩锚点。
- `tonal_structure`：黑位、对比度、中间调、高光滚降、动态范围和颗粒/洁净度形成的影调规则。

四项结论必须由跨越全片主要视觉状态的镜号或代表帧支持。只在单段出现的夕阳、夜景、爆炸、霓虹、黑白或特殊滤镜属于局部变体，保留在对应 `lighting_color`；除非它反复支配全片，否则不能写成整体风格。美术 Agent 与摄影 Agent 的证据冲突由导演裁决并锁定一份母版，不允许提示词 Agent 自行折中。

## 剪辑与 VFX Agent

这是条件 Agent。主 Agent 在启动前检查以下证据；任一项成立或无法确认时启动：

- 自动切镜候选与逐帧观察不一致，或疑似隐藏切点、叠化、闪白、动作匹配。
- 主体发生变形、替换、消失、复制或材质重组。
- 出现粒子、扫描、线框、烟雾、发光、遮罩、合成、屏幕/UI叠层。
- 前景遮挡可能隐藏人物、道具、车辆或背景替换。
- 小体积物体在高速运动中发生轨迹突变、接触、抓取、抛接或所有权转移，普通抽帧不足以确认阶段。
- 存在变速、时间重映射、异常运动连续性或多层合成。

只有全部不成立且证据明确时才跳过。跳过时主 Agent 在内部 manifest 写入 `EDIT_VFX_SKIPPED`、证据和基础剪辑结论。

启动后只输出真实切点、相对时间、阶段、遮挡关系、动作匹配和连续性风险。所有图层必须归入且只归入一类：`diegetic_display` 画内设备/面屏、`editorial_title` 后期标题、`environment_vfx` 环境特效、`ui_overlay` UI叠层、`transition_vfx` 转场特效；不得用一个综合段落混写。

## 声音指导 Agent

这是保守条件 Agent。只有以下条件全部满足且均有证据时才允许不启动：

1. 没有对白、旁白、可见口型同步或需要辨认的语音。
2. 音乐不控制切点、动作、文字或VFX节拍。
3. 没有影响剧情理解的关键拟音、提示音、冲击声或静默。
4. 全片只有单一简单环境底床，不存在声学场景切换或复杂混音。
5. 基础媒体检查没有发现需要精确定位的声音事件。

任一条件不满足或为 `UNKNOWN` 时必须启动。跳过时主 Agent 在内部 manifest 写入 `SOUND_SKIPPED`、证据和可确认的最低声音状态，不得虚构音乐或环境声。

启动后只还原对白主体、语气、口型时间、环境声、拟音、音乐、节拍、混音关系和静默；不复述剧情、摄影或画面美术。听不清内容标 `UNKNOWN`。

## Seedance 生成导演

深度模式由独立 Seedance 生成导演执行本契约；标准模式由主 Agent 以同一契约执行。负责提示词编译的 Agent 只读取导演已锁定的结构化数据，不读取原视频、关键帧全集或各专业原始报告。开始生成前先检查顶层 `visual_master.core_style`、`visual_master.visual_tone`、`visual_master.color_system`、`visual_master.tonal_structure`，再逐段检查必要资产、动作关系、摄影、本段光影、文字/VFX、声音、剪辑、连续性和禁止项。

若关键字段缺失、互相矛盾或只有无法执行的模糊词，逐项输出：

`NEEDS_INPUT｜Pxxx/SHxxx｜字段路径｜缺失或冲突原因｜责任角色`

随后立即停止，不生成部分 `prompt-data.json`、Markdown、故事板提示词或猜测内容。主 Agent 向责任角色定向补齐后，只把更新字段重新提交。明确标记且不影响执行的 `UNKNOWN` 不算缺失；关键动作、资产身份或摄影方案不能用 `UNKNOWN` 逃避补全。

数据完整后生成 schema 4.0 数据。每个镜头必须有 `present_entities`、完整动作、人物可见表演链、动态首次登场、跨镜微事件链、分层文字/VFX、冲击事件、摄影参数和自包含内部提示词；每段整段提示词写明本段所需人物、道具和场景细节。`full_prompt` 按【生成任务】→【基础设定】→【氛围质感】→【时间轴】组织；【氛围质感】不单列摄影，摄影方案位于所属时间轴节点末尾；每个事实只写一次。

每项需进入时间轴的动作、表演、首次登场、图层事件和确认冲击事件必须有唯一 ID、简洁 `timeline_fact` 与 `timeline_required=true`。`timeline_events[]` 提供相对时间和 `source_refs`；构建脚本验证引用事实属于同一镜头、节点时间与事实正向重叠，再按 ID 原样拼接 `timeline_fact`，末尾追加该镜摄影 `RECREATION_SPEC`。所有必需事实必须恰好被引用一次；遗漏、重复、无来源新增、引用不可见实体、跨镜误挂、改写事实或摄影错配均返回 `NEEDS_INPUT` 并停止。

只输出 schema 数据和最终提示词，不写分析报告。禁止 `@视频/@图片`、参考映射、入口/出口、上一段/下一段、承接和依赖前次生成的措辞。

## 轻量红队与连续性监制

这是质量门槛，不是新的分析角色。必须先运行 `scripts/validate_outputs.py`；机器校验未通过时不启动红队，由主 Agent 先修复确定性错误。

默认输入仅限：机器校验摘要、最终 manifest、内部 `prompt-data.json`、两项交付路径和紧凑的镜头/关键帧索引。不要读取各专业 Agent 的原始报告，不重新观看整段视频，不重新拉片，不生成替代剧本、分镜或提示词。

只检查机器校验无法可靠判断的 P0/P1：

- 关键剧情或镜头是否明显遗漏、错配或擅自新增。
- 人物—动作—对象关系是否造成严重歧义或与结构化证据冲突。
- 人物、载具、场景和关键状态是否出现会破坏复刻的跨文件矛盾。
- 整段提示词是否仍依赖参考素材、缺少关键生成信息，或存在严重内部复述。
- `RECREATION_SPEC` 是否缺失、互相冲突或冒充原片实测值。

只有出现具体 P0/P1 疑点时，才按镜号或片段 ID 定向读取对应文档段落；需要视觉确认时最多查看 3 张相关原片帧或 3 个短时间窗口，禁止重新遍历整段视频。

输出必须极简：

- 无 P0/P1：只写 `PASS｜P0=0｜P1=0`，立即结束。
- 有问题：每项只写 `级别｜ID/时码｜证据｜最小修复`，最多 8 项；不写视频摘要、过程复述、P2/P3 或泛化建议。

红队不亲自扩写交付。主 Agent 完成责任修复后，红队只复核变更过的 ID；最多一次初审和一次定向复核。
