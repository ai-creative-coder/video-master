# 对抗审查与验收

## 严重级别

- P0：无法交付，例如漏镜、故事板无图、提示词错配。
- P1：严重偏离，例如新增剧情、关键动作关系错误、提示词依赖参考视频、缺少资产表或逐镜摄影参数。
- P2：局部质量问题，例如器材方案不够匹配、声音细节遗漏；由主 Agent 常规检查，不进入轻量红队报告。
- P3：建议；不进入轻量红队报告。

P0/P1 必须修复。标准模式最多一轮；深度模式允许一次初审和一次仅针对已修改 ID 的复核。

## 必查项

1. 完整故事剧本与图文分镜故事板两项交付齐全，真实镜头和剧情片段连续覆盖全片；交付目录没有重复的逐镜脚本、提示词 Markdown 或 `prompt-data.json`。
2. 故事板首页有人物、主要道具、主要场景资产表；每项有代表帧、详细提示词、功能和连续性锁定。
3. 每个真实镜头至少一张代表帧，图片与对应逐镜分析及剧情段完整提示词一一映射。
4. 每镜动作明确主体、对象、空间关系、节奏和物理反馈；人物或生物另有可见表演链。
5. 每镜有 `RECREATION_SPEC` 设备名称、镜头、焦段、光圈、机位、构图、运镜、对焦和景深；用户提示词中摄影方案位于所属时间轴节点末尾，【氛围质感】不再重复单列。
6. 器材参数未冒充原片实测值。
7. `full_prompt` 与 `shot_prompt` 不含 `@视频`、`@图片`、参考映射、入口、出口、上一段、下一段、承接或要求模型记住前次生成的措辞。
8. 每条整段提示词重新写明所用人物、道具、场景、光影、文字、声音和剪辑，不能只列资产编号。
9. 同一生成内部的真实切镜和转场时间正确；跨生成一致性仅通过重复具体不变量实现。
10. 故事板与内部 JSON 同源，完整故事剧本与锁定剧情事实一致；无占位符、虚构引用或不受支持参数断言。
11. 每条 `full_prompt` 按【生成任务】→【基础设定】→【氛围质感】→【时间轴】排列，基础设定和氛围质感位于时间轴之前。
12. 静态资产只在【基础设定】定义；【氛围质感】先用同一份全片视觉母版说明核心风格、视觉基调、色彩体系和影调结构，再写本段光影与色彩、声音；本段光影不重复或改写母版，时间轴不全文复述这些内容；摄影只出现在所属时间节点末尾；资产库锁定项不逐条灌入片段连续性，禁止项不反向复述正向要求；不存在逐字或近似重复长句。
13. 内部 manifest 对剪辑/VFX 与声音 Agent 记录 `STARTED` 或 `SKIPPED` 及证据；跳过理由满足对应门控条件。
14. 负责提示词编译的 Agent 只读取锁定结构化数据；最终交付不存在 `NEEDS_INPUT`、缺失关键字段或未解决冲突。深度模式由 Seedance 生成导演执行，标准模式由主 Agent 执行，质量门槛相同。
15. `timeline_events[]` 已将动作、文字和 VFX 合并为自然语言事件；`full_prompt` 不暴露“主体/位置关系/对象或目标/表演状态/物理反馈”等内部字段标签，不为非人物对象填充无价值情绪。
16. 同一 UI/VFX 阶段在时间轴只出现一次；逐词时码只服务明确同步节点；`timeline_continuity` 只描述可见结果，不包含换底片、Alpha 通道或合成节点等制作过程。
17. `action_beats[]` 的人物情绪、动作与物理反馈只绑定本镜 `present_entities`；人物有完整可见表演链，非人物无伪情绪字段。
18. 每位人物首次可见时存在且只存在一个动态登场事件；此前状态、来源空间、触发、方向、位置、最先露出部位、揭示动作、初态、第一动作、完整建立状态与观察者反应均可执行，并有至少两张属于同镜的证据帧。首次登场事实、时间轴节点和镜号一致且时间正向重叠。
19. 画内面屏、后期标题、环境 VFX、UI 和转场分类明确；旧的混合 `text_graphics` 字段不得残留。
20. 每个 `timeline_required=true` 的逐镜事实由唯一 ID 恰好进入一次时间轴；同一节点的来源事实属于同一真实镜头并与节点时间正向重叠；构建文字等于源 `timeline_fact` 拼接后加该镜摄影方案，无遗漏、重复、跨镜误挂、无来源新增、改义或摄影错配。
21. 短促冲击事件拥有峰值前/中/后加密帧；原因、目标、即时反应和物理结果得到验证，证据不足时不作确定性因果判断。
22. 小物体离地、接触、抛接、抓取、携带、返回、方向突变和观察者视线追踪没有被省略；跨镜阶段使用同一交互链 ID、类型和对象 ID，相邻阶段的 `state_out/state_in` 完全一致。所有权转移包含触发/踢飞、接触/抓取、携带/返回、结果/观察者反应四类阶段。

先使用 `scripts/validate_outputs.py` 做机器检查。只有机器通过后才启动轻量红队；红队只审查 P0/P1，默认不读取专业原始报告或整段视频。机器通过不代表动作关系和器材方案一定正确。
