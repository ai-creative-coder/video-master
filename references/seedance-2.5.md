# Seedance 2.5 自包含提示词规则

## 核心原则

参考视频只用于分析，不是生成输入。每条提示词都必须能在新的空白生成任务中直接使用，不要求用户再次上传参考视频、上一段生成结果或关键帧。

禁止在 `full_prompt` 和 `shot_prompt` 中出现：

- `@视频1`、`@图片1` 或任何虚构素材编号。
- “参考映射”“参考原片”“按照参考视频”。
- “入口”“出口”“承接上一段”“延续上一段”“忠实复刻上一段硬切”。
- 依赖模型记住前一次生成的“保持人物/场景一致”，但不重复具体特征。

源时间码只用于故事板和分析溯源，不写进生成提示词。生成提示词只写目标时长和片段内部相对时间。

## 缺失字段停止机制

负责提示词编译的 Agent 只消费导演锁定的结构化数据，不通过重新观看视频自行补洞；深度模式由 Seedance 生成导演执行，标准模式由主 Agent 执行。开始逐段生成前必须先具备全片 `visual_master` 的核心风格、视觉基调、色彩体系和影调结构；每个剧情片段还必须具备本段资产、完整动作关系、摄影、本段光影、文字/VFX、声音、剪辑、连续性和禁止项。

缺失、冲突或不可执行时只输出 `NEEDS_INPUT｜Pxxx/SHxxx｜字段路径｜原因｜责任角色` 并停止；不得猜测、生成部分提示词或把占位符写入交付。主 Agent 定向补齐后再继续。证据确实无法确认的非关键细节可用 `UNKNOWN`，关键资产身份、关键动作和 `RECREATION_SPEC` 不得为空。

## 自包含资产描述

每条整段提示词必须重新写出本段会出现的资产：

- 人物：身份、年龄感、脸型、肤色或材质、五官、发型、体型、服装、配饰、污损状态和表演习惯。
- 道具：类别、形状、尺寸关系、材质、颜色、磨损、文字、持有方式和交互方式。
- 场景：地点、时代、空间结构、前中后景、材质、陈设、天气、光源方向、色温和色彩体系。

资产编号可用于内部核对，但不能代替自然语言描述。“角色保持一致”“场景不变”必须跟随具体不变量。

## 完整动作关系

不得只写“人物走来、转身、看向镜头”。每个动作节拍必须明确：

1. 主体是谁。
2. 主体位于画面和场景的什么位置。
3. 主体以什么动作作用于谁或什么对象。
4. 对象与主体的距离、方向、遮挡和接触关系。
5. 动作开始、发展、结束的节奏和持续时间。
6. 主体情绪、视线、重心、速度和力度。
7. 对象、衣物、道具、粒子或环境的物理反馈。

多人镜头分别描述每个人的动作，不用“他们互动”“双方靠近”等模糊总结。

每镜先锁定 `present_entities`。人物或生物的动作必须有可见表演链：情绪意图如何体现为表情与视线，身体怎样预备、执行、延续并收势。情绪、肢体、服装或物理反馈不得从上一镜复制给本镜未出现的角色；车辆、道具、环境和图形不填写人物表演状态。

每位人物全片首次可见时单独描述：出现前是否在镜外或被桌面、门框、前景等遮挡，来自哪个具体空间，由什么动作或切镜揭示，最先露出哪个身体部位，从哪个方向进入画面哪个区域，怎样完成揭示动作、第一动作和完整建立，在场人物是否有可见反应。至少用两张属于该镜的证据帧锁定登场过程；探头、起身、破门或遮挡解除等动作式登场优先三帧。不要只写“某人出现”，也不要把“从桌下突然探出头”改成“硬切到身体”。

小体积物体发生离地、抛接、抓取、携带、轨迹改变或跨镜所有权转移时，以同一交互链 ID、类型和对象 ID 逐阶段描述触发主体、动作对象、接触点、进入状态和离开状态；上一阶段离开状态必须原样成为下一阶段进入状态。所有权转移至少保留触发/踢飞、接触/抓取、携带/返回、结果/观察者反应四类阶段。例如“人物踢起地面物体→物体进入空中→飞行动物用脚抓住→携物飞回→人物抬头目视追踪”不能压缩成“鸟从天空飞过”。

## 文字与 VFX 分层

- `diegetic_display`：角色面屏、手机、仪表、招牌等存在于故事空间的文字或图像。
- `editorial_title`：后期叠加标题、字幕、CTA。
- `environment_vfx`：烟、火、粒子、能量、天气等处于场景空间的特效。
- `ui_overlay`：屏幕坐标 UI、按钮、光标、卡片。
- `transition_vfx`：只负责镜头转换的闪白、遮挡、溶解或图形转场。

同一事件只能归入一类；分别说明内容、外观变化、空间/屏幕位置与真实遮挡关系。

## 事实锁定时间轴

逐镜动作、首次登场、图层与确认冲击事件分别生成唯一事实 ID 和一句简洁 `timeline_fact`。时间轴提交 `source_refs`，由脚本验证镜号与时间重叠后原样编译，并在节点末尾追加所属镜头摄影方案；所有 `timeline_required=true` 的事实必须恰好出现一次。需要修改意思时回到逐镜事实源，不直接改时间轴文字。

对枪声、撞击、打击、爆炸等短促音频瞬态，检查前后约 0.20 秒的加密帧，依次确认声音/可见原因、作用目标、即时反应和物理结果。只听到声音但看不清因果时标 `UNCERTAIN`，不得把“中枪后失衡落水”简化为“人物主动掉入水中”。

## 摄影复刻参数

每个真实镜头都提供 `RECREATION_SPEC`，至少包括：

- 摄影设备名称或虚拟电影摄影机方案。
- 镜头名称或类型。
- 焦段。
- 光圈。
- 机位高度与角度。
- 构图。
- 运镜方向、轨迹、速度和稳定方式。
- 对焦主体、焦点变化和景深。

这些是复现画面的建议方案，不得声称是原始设备实测值。设备选择应与画面质感匹配，不要为所有镜头机械套用同一套参数。

## 整段提示词结构

每条提示词负责一个完整剧情片段，固定采用以下层级；【基础设定】和【氛围质感】必须先于【时间轴】：

1. 【生成任务】：时长、画幅、帧率感、整体风格和剧情目标。
2. 【基础设定】：
   - 人物角色：本段实际出现人物的身份、外貌、服装、体态和表演习惯。
   - 道具与车辆：本段实际出现物件的形态、尺寸、材质、颜色、文字和交互方式。
   - 场景环境：地点、空间结构、前中后景、材质、陈设和天气。
   - 连续性要求：只列生成过程中必须锁定、且前述资产描述尚未表达的状态。
   - 禁止项：只列高概率且会显著破坏复刻结果的错误。
3. 【氛围质感】：
   - 全片视觉母版：固定按核心风格、视觉基调、色彩体系、影调结构四项输出。它描述贯穿全片的类型与时代语言、写实/风格化程度、情绪和材质气质、主辅色与饱和度关系、黑位/对比度/中间调/高光滚降和动态范围；不能只写“电影感、高级、真实、氛围感”。
   - 本段光影与色彩：只写剧情、地点、天气、时间或特效导致的局部光源、色温、曝光和视觉锚点变化；不改写或同义重复全片视觉母版。
   - 声音设计：音乐、环境声、对白、拟音、混音以及确有必要的相对时间。
4. 【时间轴】：把剧情位置、动作关系、人物表演、对象状态转移、文字、VFX 和镜内连续性合并为按片段内部相对时间排列的自然语言事件。每条采用“时间｜场景位置与谁做什么｜关键状态变化与必要反馈｜摄影 RECREATION_SPEC”；摄影固定放在该节点最后。时间轴引用已定义资产，不重新描述静态外观；光影和声音不在这里全文复述。

内部逐镜事实完整保存主体、对象、空间、时序、表演和物理反馈。负责提示词编译的 Agent 只按事实 ID 生成 `timeline_events[]`，用户可见文本不得出现字段清单。

`timeline_events[]` 写作规则：

- 一条事件只描述一个连续动作或一组不可拆的因果变化，优先使用“谁做什么，导致什么可见结果”的自然语序。
- 空间、对象、情绪和物理反馈已经能从动作句明确理解时，不再换一种说法追加。
- 只有人物或具有明确情绪表现的生物才写表演状态；车辆、UI、粒子、道具和环境不写“中性、克制、无情绪”等空信息。
- 同一文字、UI 或 VFX 阶段不得同时在动作事件和另一条视觉事件中重复；将时间与可见结果合并为唯一事件。
- 每个时间节点只能引用同一真实镜头内且与节点时间正向重叠的事实；首次登场或动作事实不能因边界舍入被提前挂到上一镜。节点末尾只追加该镜的摄影方案。
- 逐词时码只在用户明确要求逐词口型，或某个词必须同步触发文字、CTA、动作或 VFX 时保留；其他对白只写整句起止时间和准确口型。
- `timeline_continuity` 只写成片可见要求，例如“连续侧跟、无硬切、遮挡前后道路方向和主体速度一致”。删除“换底片、Alpha 通道、合成节点、渲染通道”等不会改变目标画面的制作过程。

## 信息价值与去重

- 同一事实只放在一个栏目；不要先完整定义，再在时间轴换一种说法重写。摄影只随时间节点出现，不在【氛围质感】另列。
- 静态特征放【基础设定】；全片稳定风格放【氛围质感】的“全片视觉母版”；本段光影只写相对母版的差异；随时间变化的事件放【时间轴】。
- 资产的 `description_prompt` 只负责静态身份与外观，不预写其他剧情段才会发生的姿态、交互或状态；这些变化进入对应时间轴。
- 资产库的 `continuity_lock` 用于故事板和跨段归纳，不直接整段注入 `full_prompt`。`segment_consistency` 从中提炼本段真正需要锁定、且资产定义尚未表达的组合关系与动态状态。
- `avoid` 只保留尚未由正向要求和 `segment_consistency` 排除的高风险错误，不把“保持A”再次改写成“禁止不A”。
- 多个镜头使用相同本段光影或声音方案时只写一次；只有发生实质变化才按相对时间分别列出。摄影方案即使相同，也由构建器在每个所属时间节点末尾明确写出，以锁定该节点的镜头执行。不得在“本段光影与色彩”里用近义词重新描述全片母版。
- 删除不改变主体身份、空间关系、动作时序、摄影质感、声音或生成边界的修饰语。禁止用“真实、自然、稳定、高级”等近义词堆叠替代可执行描述。
- 跨剧情片段为了独立生成可以重复必要资产；同一条 `full_prompt` 内不得出现逐字重复或近似重复的长句。
- 内部结构化字段与用户提示词分层：`action_beats[]` 是校验真源，`timeline_events[]` 是从中编译出的自然语言展示层，不得反向成为第二套事实来源。

同一片段内部可以写“2.3 秒硬切到下一个镜头”，因为这是一次生成内部的剪辑指令。不要描述该片段如何从另一生成任务进入，也不要要求下一次生成延续本段。

跨片段一致性通过数据归纳实现：分析相邻片段后，把共同的人物外观、场景几何、光向、天气、道具状态和声音基调分别写入两条独立提示词。每条提示词独立成立，但其内部仍遵守一次定义原则。

## 文字与声音

画面文字写出准确内容、语言、字体气质、颜色、位置、出现时间和持续方式；无法确认的小字标 `UNKNOWN`，不补写。

声音写出对白主体、语气、口型时间、环境声、拟音、音乐风格、节拍和静默。音乐名称不确定时描述可听特征，不猜曲名。

## 修复提示词

修复提示词只修改失败项，并再次写清相关资产与动作关系；不得说“参考原视频修复”或依赖前次提示词上下文。若修复工具本身要求提供上一版生成结果，应由用户在实际修复时另行添加素材，而不是写进本制作包的默认提示词。
