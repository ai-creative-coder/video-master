# 标准模式工作流

标准模式 Token 相对指数以常规双子 Agent 运行为 `100%`。分析角色更少，但两项交付和提示词质量门槛与深度模式一致。

## 编排

- 主 Agent 负责证据包、真实镜头与剧情段裁决、最终综合、提示词编译、故事板和验证。
- 默认启动 1 个视觉综合 Agent。
- 叙事与声音综合 Agent 按下述证据门控；因此标准模式通常使用 1–2 个子 Agent。
- 不启动独立提示词、剪辑/VFX、声音或备份 Agent。复杂剪辑/VFX 由视觉综合 Agent 在同一契约内处理，声音由条件启动的叙事与声音综合 Agent 处理。
- 主 Agent 在内部 manifest 记录条件 Agent 的启动或跳过结论及证据。

## 视觉综合 Agent

视觉综合 Agent 是可见画面事实的唯一责任角色。先跨全片提炼一份 `visual_master`，再逐镜输出镜头功能、可观察动作关系、景别/机位/构图/运镜、本段光影/色彩、场景/服装/道具、真实切点和可见 VFX；不得推断人物动机、复述对白含义或扩写声音。

`visual_master` 必须覆盖全片的 `core_style`、`visual_tone`、`color_system`、`tonal_structure`。分析时查看开头、中段、结尾及所有主要视觉状态的代表帧，区分“反复出现、支配全片的稳定规则”和“只服务单段剧情的局部变化”。四项内容要写成可执行的画面规则：说明时代/类型/写实或风格化程度、情绪与材质气质、主辅色和饱和度关系、黑位/对比度/高光滚降与动态范围；禁止只堆“电影感、高级、真实、氛围感”等空泛形容词。

逐镜 `lighting_color` 只记录本段相对全片母版发生的光源、天气、时间、色温、曝光或视觉锚点变化，不重新改写全片风格。局部画面与母版表面不同时，明确它是受剧情、地点或时间影响的受控变体；不得据此把全片重新定调。

摄影部分无论模式都必须提供 `RECREATION_SPEC`：设备名称、镜头名称或类型、焦段、光圈、机位、构图、运镜、对焦和景深。将其作为可行复刻方案，不冒充原始元数据。

同时归纳人物、主要道具和主要场景资产；每项给出代表帧、详细生成提示词、叙事功能和连续性锁定。

动作写入 `action_beats[]`，主体与对象必须绑定本镜 `present_entities`。人物/生物必须增加 `performance_chain`，按“情绪意图→可见表情与视线→动作预备→执行→延续→收势”记录可见表演；道具、车辆、环境或图形不得继承人物情绪、服装反馈或肢体描述。

视觉综合 Agent 还必须做一次“微事件与所有权转移扫描”：逐镜检查小物体是否被踢起、抛出、接住、抓取、携带、掉落或改变运动方向，以及人物视线是否随后追踪该物体。跨镜连续动作使用同一 `interaction_chain_id`、`interaction_kind` 和 `interaction_object_ids`；所有权转移必须覆盖“触发/踢飞、接触/抓取、携带/返回、结果/观察者反应”四类阶段。每阶段写 `interaction_phase`、`state_in` 和 `state_out`，并把上一阶段 `state_out` 原样复制为下一阶段 `state_in`。若运动模糊或遮挡使接触点无法确认，定向补抽接触前/中/后帧；仍不能确认则标 `UNKNOWN`，不得压缩为无对象的“飞过”或“看向天空”。

每个人物首次进入全片可见范围时写动态 `first_appearance_events[]`：出现前状态、具体来源空间、揭示触发、进入方向、画面区域、最先露出的身体部位、初始姿态、揭示动作、第一动作、完整建立后的状态与在场角色反应。至少引用两张属于首次登场镜头的证据帧；探头、起身、破门、从遮挡后显现等动作式登场优先使用“揭示前/最初可见/完整建立”三帧。首次可见事实和时间轴必须落在同一镜头且具有正时间重叠，不能挂到上一镜。画内面屏、后期标题、环境 VFX、UI 和转场分别写入不同 `layer_type`，不得混成一个文本字段。

剪辑/VFX 仅按证据展开：普通硬切只记录切点；主体变形/替换/消失/复制、粒子/扫描/线框/UI 叠层、遮挡藏切、变速或疑似多层合成出现时，才补充阶段、遮挡关系和连续性风险，不为简单镜头生成冗长 VFX 分析。

## 叙事与声音 Agent

仅在以下任一情况成立或为 `UNKNOWN` 时启动：

- 存在对白、旁白、可见口型或需要辨认的语音。
- 存在多人物关系、动作因果、叙事动机或剧情理解不能仅靠可见动作确定。
- 音乐控制切点、动作、文字或 VFX 节拍。
- 存在影响剧情的关键拟音、提示音、冲击声、静默或声学场景切换。

只有以上各项均不成立且证据明确时才跳过，并记录 `NARRATIVE_SOUND_SKIPPED`、证据与可确认的最低声音状态。

启动后只补充故事因果、人物关系与意图、影响表演的情绪、可确认对白/字幕/口型，以及音乐、环境声、拟音和混音关系。使用 `shot_id/beat_id` 引用视觉综合 Agent 的动作，不重新描述已经成立的可见动作、摄影、美术或 VFX。

## 主 Agent 综合

1. 以视觉综合 Agent 的可见事实为动作主干，把叙事与声音增量合并到对应 `shot_id/beat_id`；解决冲突，证据不足保留 `UNKNOWN`。
2. 生成完整故事剧本；逐镜结构化分析直接进入图文故事板，不再另写重复的逐镜分镜脚本。
3. 建立 `asset_library`，并锁定视觉综合 Agent 的 `visual_master`；同一资产只保留一份标准描述，再按每段实际状态补充污损、光照和动作变化。
4. 以“标准模式的 Seedance 生成导演”身份执行与深度模式相同的缺失字段预检。任一关键字段缺失、冲突或不可执行时，只输出 `NEEDS_INPUT｜片段/镜号｜字段路径｜原因｜责任角色` 并停止提示词构建；定向补齐后再继续，不猜测、不生成半成品。
5. 生成与深度模式相同 schema 4.0 的 `prompt-data.json`。每个镜头有 `present_entities`、代表帧、完整 `action_beats[]`、跨镜微事件链、动态首次登场、分层文字/VFX、冲击事件、摄影参数和内部校验用 `shot_prompt`。
6. 每条需进入时间轴的逐镜事实拥有唯一 ID、`timeline_fact` 与 `timeline_required=true`。`timeline_events[]` 按时间引用 `source_refs`；构建器先验证来源事实、时间轴节点和真实镜头三者一致且时间正向重叠，再逐字编译事实，并把该镜摄影 `RECREATION_SPEC` 自动追加到节点末尾。不得手工改写或把下一镜的首次登场提前挂到上一镜；遗漏、重复、串镜、无来源新增、改义或摄影错配立即停止。
7. 逐条清除参考视频映射、入口/出口、承接上一段等依赖上下文的措辞。
8. 做一次语义去重：静态身份只在【基础设定】；全片核心风格、视觉基调、色彩体系和影调结构只写在【氛围质感】的“全片视觉母版”；本段光影与色彩只补充相对母版的必要差异；随时间变化的可见事件和所属镜头摄影方案只在【时间轴】。【氛围质感】不再单列摄影方案。删除不增加身份、动作、时序、质感或生成边界的句子。时间轴不得显示内部字段标签，非人物对象不写空泛情绪，同一 UI/VFX 时序只出现一次。
9. 从同一内部 `prompt-data.json` 生成图文故事板，并把每段完整提示词与存在的专项修复提示词嵌入故事板；不再生成独立提示词 Markdown。每个真实镜头至少一张代表帧；枪声、撞击、打击、爆炸等音频瞬态候选前后约 0.20 秒加密抽帧，人工验证原因→目标→反应→物理结果后才写入 `impact_events[]`。

标准模式不得因 Agent 更少而缩短提示词、遗漏摄影设备/镜头/焦段/光圈/运镜、声音、文字/VFX、连续性或禁止项。它与深度模式的格式和字段质量相同，差异仅在专业拆分数量、独立复核深度和必要的关键帧密度。

## 审查

先运行确定性验证。视频超过约 60 秒、镜头超过约 20 个、存在复杂 VFX/多人物，或主 Agent 发现 P0/P1 候选时，按 [agent-contracts.md](agent-contracts.md) 启动轻量红队。机器校验未通过时先直接修复，不启动红队。

标准模式最多一轮责任修复。仍有 P0/P1 时如实报告。
